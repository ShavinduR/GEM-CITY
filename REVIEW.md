# FACET / gemcity.lk: code review and redesign

## 1. What was wrong

### Bugs that visitors saw
| # | Problem | Effect |
|---|---|---|
| 1 | **40 broken image paths.** HTML/CSS asked for `hero1.jpg` while the files were `.webp`, and jewellery photos were referenced as `images/jewelleryw/` but stored in `images/ui/jewelleryw/` | Homepage hero was a black box; **every photo on the jewellery page was missing** |
| 2 | **68 "Inquiry" buttons linked to `#`** | The main conversion action did nothing |
| 3 | Footer links (Terms, Privacy, Money-back), social icons and the newsletter form all went nowhere | Dead ends at the point of building trust |
| 4 | Three different emails (`sales@gemcity.lk`, `sales@facet.com`) and two brand names (FACET vs Gem City) | Looks unprofessional; a buyer wonders if it's the same company |
| 5 | Testimonials duplicated in the HTML (the same 3 reviews twice); two reviewers shared one photo, and all photos were missing | Social proof looked fake |
| 6 | 23 jewellery photos (mostly pendants and sets) were all filed under "Rings" | Filters returned the wrong products |
| 7 | Four WebGL canvases rendered the same ring 60× a second, all the time, even off-screen | Heavy battery and CPU drain on phones |
| 8 | Exchange-rate API called on every page view, even for LKR visitors | Wasted requests and a console error when offline |

### Bad practices in the code
- **~500 inline `style="…"` attributes** and a **730-line commented-out stylesheet** inside `index.html`, so design changes had to be made in dozens of places.
- **Product data hand-copied into HTML**: 68 near-identical blocks of ~25 lines each. Adding one stone meant copying markup by hand.
- **`onclick=` / `onmouseover=` attributes** and functions on `window`, mixing behaviour into markup.
- **Font Awesome (~90 KB CSS + fonts)** loaded for about 15 icons; Google Fonts loaded from two extra domains.
- **Images up to 1.9 MB** (PNG founder photo) and full 3000 px photos sent to phones; no `srcset`, `width`/`height` or lazy-loading strategy, causing layout shift.
- **Accessibility:** no skip link, clickable `div`s, mobile menu without `aria-expanded`, form fields without linked labels, icon-only links without names, low-contrast grey text, no `prefers-reduced-motion` support.
- **SEO:** no canonical URLs, sitemap or robots.txt; `og:image` pointed to a missing file; schema listed unverified social profiles; duplicate `<h1>`s on article pages.
- **Claims that create legal risk:** "outperforming traditional asset classes" (investment advice without a disclaimer), and product names that contradict their photos (see Owner action list).

## 2. Why I changed it

### Architecture: static HTML + modular CSS + vanilla ES modules (no framework)
This is a catalogue of ~70 pieces that sells through conversation (WhatsApp/viewing), not a cart checkout. React/Tailwind/Node would add a build pipeline and 40–150 KB of JavaScript without improving anything for the buyer. The site now:
- ships **0 KB of framework code**; JavaScript is split by feature and loaded only on pages that need it (catalogue, form, 3D viewer)
- deploys anywhere by uploading the files (GitHub Pages, Netlify, cPanel): no build step to break
- keeps product **data separate from presentation**: one line in `assets/js/data/gems.js` adds a stone everywhere (grid, search, dialog, WhatsApp message, SEO schema)

```
assets/
  css/tokens.css      design tokens: colours, type scale, spacing, motion (edit the brand here)
  css/base.css        reset, typography, focus styles, reduced-motion
  css/components.css  header, buttons, cards, catalogue, dialog, forms, footer, WhatsApp button
  css/pages.css       hero, category tiles, 3D viewer, contact, article typography
  js/config.js        phone, email, WhatsApp number, currencies: single source of truth
  js/main.js          entry point; loads feature modules on demand
  js/modules/         nav, reveal, whatsapp, currency, catalog, product-view, product-dialog, inquiry-form, ring-viewer
  js/data/            gems.js, jewellery.js (the inventory)
  icons.svg           28 icons in one cached sprite (replaces Font Awesome)
  fonts/              self-hosted Montserrat variable font (38 KB, one file)
images/opt/           responsive WebP versions generated by scripts/optimize_images.py
```

### UI/UX: premium, minimal, dark
- **Dark luxury palette** (near-black, ivory, one gold accent) where **every text colour passes WCAG AA**, checked numerically, for example gold on black at 9.4:1.
- **One typeface (Montserrat)** in light weights for display and medium for UI, on a fluid type scale (`clamp()`) that looks right from 320 px to 4K.
- **More white space:** section padding scales with the viewport, so content breathes instead of stacking.
- **Real product photography leads.** Your studio jewellery shots are authentic and consistent, so they now come first on the homepage. Small loose-gem photos sit "on a plinth" (contained on a soft light background) instead of being stretched and blurred.

### Trust: answering the buyer's fear before they ask
Buying a stone from overseas feels risky. The page now removes that risk step by step:
1. **Announcement bar + hero proof points:** live video before you pay · 14-day money-back · insured delivery.
2. **Trust bar:** direct from Ratnapura · lab-reported · insured worldwide · flexible payment.
3. **"How buying works"** in 4 steps (choose → see it live → pay → insured delivery).
4. **Founder story + face** (gemologist sourcing directly), with a photo of real mining.
5. **FAQ** answering the six questions buyers actually ask (also marked up as FAQ schema for Google).
6. **Real policies page** (shipping, returns, certification, payment, privacy) so the footer promises link to something.
7. **One consistent identity:** one brand, one email, one phone, everywhere.

### Conversion: one tap from interest to conversation
- **Every product card has "Ask on WhatsApp"**, pre-filled with the product name, reference, guide price and a link back to it, so the gemologist knows exactly which stone the buyer means.
- **Product quick-view dialog** with gallery, specs and three CTAs (ask, live video, book viewing), placed directly under the price.
- **Shareable links:** `all-gems.html?type=blue`, and `all-gems.html#A3` opens that stone. Paste them straight into WhatsApp chats.
- **Floating WhatsApp button** with a page-specific opening message, kept clear of menus and dialogs.
- **Inquiry form** sends to WhatsApp *or* email (buyer's choice), validates inline with accessible errors, and can be pre-filled from links (`contact.html?interest=private-viewing&ref=A1`).
- **"From LKR X" guide price** instead of a wide range: honest, and less intimidating.
- **Empty search results** offer "Ask us to source it" instead of a dead end.

### Performance and SEO
- Hero image preloaded with `fetchpriority="high"`; everything else lazy-loaded with explicit `width`/`height` (no layout shift).
- Jewellery photos cut from ~1 MB to **15–100 KB** each at 480/960 px via `srcset`.
- 3D viewer (three.js) downloads **only when scrolled into view**, renders **only while visible**, and respects reduced motion.
- Measured on load: homepage ~92 KB, catalogue ~64 KB, articles ~34 KB (excluding lazy images below the fold).
- Canonical URLs, Open Graph images, `sitemap.xml`, `robots.txt`, web manifest, and JSON-LD for JewelryStore, ItemList/Product, Article and FAQPage.

### How it was tested
An automated browser test (Playwright) covered: all 11 pages load with no JS errors, dead links or broken images; filters, search, sort and URL sharing; dialog open, deep link, keyboard arrows, Esc and focus return; currency switch and persistence; form validation, pre-fill and WhatsApp hand-off; mobile menu and no horizontal scroll on iPhone. Accessibility checks on every page covered alt text, labels, accessible names, unique IDs, heading order, `lang` and meta description. Lighthouse itself could not be run in this environment, so run it once after deploying (Chrome DevTools → Lighthouse).

## 3. Owner action list (things code cannot fix)
1. **⚠ Replace the loose-gem photos (most important).** Many have printed captions that contradict the listing: A3 "Ceylon Blue Sapphire" shows *Blue Topaz*, A8 *Aquamarine*, A10 *Kunzite*, L1 *Zircon*, E1 *Emerald*, P1 *Pink Amethyst*, O1 *Garnets*. Selling a stone under a different name than its photo is a serious trust and legal problem. They are also only 232 px wide. Photograph each stone like your jewellery (same black-velvet setup) and save as `images/gemw/1/<ID>.webp`.
2. **Testimonials:** keep them only if they are real clients. Better still, link your Google Business reviews.
3. **Jewellery details:** names describe what is visible in each photo. Confirm the actual gemstone and metal for each piece in `assets/js/data/jewellery.js`.
4. **Policies:** review `policies.html` with your advisor (dispatch times, return conditions).
5. **Social links:** add your real Instagram/Facebook URLs to the footer once confirmed (they were removed because the old links were unverified).
6. **Certificates:** the site says premium stones have NGJA/GIA/GRS reports. Make sure each listing's report matches.

## 4. Suggested next steps for engagement
- **Video on hover:** a 3-second muted loop of each stone rotating under light (`<video muted loop playsinline preload="none">`, started on `mouseenter`). Sparkle sells colour better than any still.
- **Compare drawer:** let buyers "♡ shortlist" up to 3 stones (localStorage) and send the whole shortlist in one WhatsApp message.
- **Scroll-linked hero:** `animation-timeline: view()` (CSS scroll-driven animations) to slowly scale the hero photo as the page scrolls, with no JavaScript. Wrap in `@supports` and `prefers-reduced-motion`.
- **Gem shimmer accent:** a slow moving gradient across gold headings on hover (`background-clip: text` with an animated `background-position`), used sparingly.
- **View Transitions API** (`@view-transition { navigation: auto; }`) for a smooth cross-fade between pages in Chrome and Edge, with zero JavaScript.
- **Analytics:** each WhatsApp button carries `data-track` (`wa-card`, `wa-dialog`). Connect a privacy-friendly tool (Plausible or Umami) to see which stones get the most inquiries.
- **Individual product pages** (e.g. `/gems/a3.html`) generated from the data file, once real photos exist, so each stone can rank in Google.
